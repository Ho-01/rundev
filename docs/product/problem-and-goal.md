# RunDev가 해결하려는 문제와 목표

## 한 문장 정의

RunDev는 여러 개발 도구에 흩어진 하루의 활동을 사용자가 안심하고 이해할 수 있는
하나의 로컬 기록으로 모으고, 그 기록을 부담 없는 성장 경험으로 바꾸는 데스크톱
컴패니언이다.

## 우리가 해결하려는 문제

오늘날 개발자의 작업은 IDE, 터미널, 브라우저, Codex, Claude Code, Cursor 등 여러
도구에 나뉜다. 각 도구는 일부 사용량이나 기록을 보여주지만 서로 기준이 다르고,
개발자는 “오늘 실제로 얼마나 몰입했고 어떤 도구를 얼마나 사용했는가”를 한눈에
확인하기 어렵다. 하루가 끝나도 남는 것은 여러 대시보드의 숫자와 막연한 피로감뿐이며,
작은 진전이 축적되고 있다는 감각은 약하다.

기존 생산성 추적 제품은 이 문제를 해결하는 과정에서 또 다른 문제를 만든다. 상세한
키 입력, 화면, 창 제목, 코드 또는 대화 내용을 수집하거나, 서버 계정과 조직용 평가
지표를 전제로 하는 경우가 많다. 개인 개발자에게는 필요한 요약보다 감시받는 느낌,
설정 부담, 데이터 유출 위험이 더 커질 수 있다. 반대로 개인정보를 지키기 위해 아무것도
측정하지 않으면 자신의 흐름과 꾸준함을 돌아볼 근거가 사라진다.

따라서 핵심 문제는 단순한 “개발 시간 측정”이 아니다. **내용을 들여다보지 않으면서도
분산된 개발 활동을 충분히 정확하게 요약하고, 그 결과를 압박이나 평가가 아닌 지속할
동기로 돌려주는 것**이다.

## 제품 가설

사용자가 명시적으로 허용한 최소 신호만 기기 안에서 집계하고, 이를 짧은 요약과 캐릭터의
성장으로 표현하면 다음 두 가지를 동시에 달성할 수 있다.

1. 사용자는 여러 도구를 돌아다니지 않고도 오늘의 개발 활동과 AI 사용량을 이해한다.
2. 원문 수집이나 외부 계정 없이도 자신의 꾸준함을 안전하게 기록하고 계속할 이유를 얻는다.

숫자는 사실을 전달하되 사용자를 채점하지 않는다. 캐릭터, 레벨, 활동 잔디와 작은
상호작용은 경쟁을 만들기 위한 장치가 아니라, 보이지 않던 노력을 가볍게 체감하게 하는
표현 수단이다.

## 목표 지점

RunDev가 도달하려는 상태는 **설치 후 몇 분 안에 이해되고, 이후에는 관리하지 않아도
신뢰할 수 있는 개인 개발 활동 컴패니언**이다.

- Windows와 macOS에서 트레이에 가볍게 상주하고 창을 닫아도 안정적으로 기록한다.
- 개발 집중시간, 입력 횟수, 연결한 AI 도구의 일간 집계를 한 화면에서 같은 언어로
  설명한다.
- 키 입력 내용, 프롬프트, 응답, 소스 코드, 화면을 수집하지 않으며 기본 데이터는
  로컬 SQLite에만 둔다.
- 각 연동의 출처, 권한, 마지막 갱신 시각과 오류를 사용자가 이해하고 직접 복구할 수
  있게 한다.
- 업데이트와 DB 마이그레이션 이후에도 기록과 OS 권한이 예측 가능하게 유지된다.
- 하루의 결과가 XP, 레벨, 캐릭터 상태와 활동 기록으로 축적되어 작은 성취감을 준다.

## 성공을 판단하는 기준

기능 수보다 다음 경험이 일관되게 성립하는지를 본다.

- **빠른 이해:** 처음 실행한 사용자가 수집 범위와 연동 상태를 몇 분 안에 설명할 수 있다.
- **신뢰성:** 하루 동안 앱을 의식적으로 관리하지 않아도 누락·중복 없는 요약을 확인한다.
- **투명성:** 숫자가 어디서 왔고 왜 비어 있는지 화면에서 알 수 있으며 스스로 복구한다.
- **프라이버시:** 원문 데이터와 인증 토큰이 저장·전송되지 않는다는 약속을 구조와
  검증으로 지킨다.
- **지속성:** 사용자가 감시나 죄책감보다 자신의 누적된 진전 때문에 다시 앱을 확인한다.

## 명확한 비목표

RunDev는 직원 감시, 생산성 점수화, 팀 랭킹, 소스 코드 분석 도구가 아니다. 로그인,
클라우드 동기화, 친구·경쟁·결제 기능도 별도 제품 결정 전에는 추가하지 않는다. 기능
확장이 로컬 우선 원칙이나 사용자의 통제권을 약화한다면, 편의보다 신뢰를 우선한다.
