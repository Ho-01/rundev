# 0008. Claude Code 사용량은 로컬 OpenTelemetry로 수집

- 상태: Accepted
- 날짜: 2026-07-28

## 맥락

Claude Code의 토큰 사용량을 정확히 집계하되 계정 자격 증명, 프롬프트, 응답,
도구 내용을 RunDev가 읽거나 저장해서는 안 된다. 여러 터미널과 IDE에서 실행한
Claude Code 세션도 한 곳으로 모을 수 있어야 한다.

## 결정

사용자가 UI에서 명시적으로 동의하면 RunDev가 `~/.claude/settings.json`의 `env`에
Claude Code 공식 OpenTelemetry 로그 설정을 추가한다. 로그는
`127.0.0.1:43182/v1/logs`의 RunDev 로컬 수집기로 전송한다.

- `claude_code.api_request` 이벤트의 토큰 합계만 SQLite에 저장한다.
- 프롬프트, 응답, 도구 상세와 원시 API 본문 수집 옵션은 모두 `0`으로 고정한다.
- 임의 프로세스의 전송을 막기 위해 연동마다 생성한 비밀 헤더를 검증한다.
- 기존 관리 대상 환경 변수는 연동 전에 보관하고, 연동 해제 시 RunDev가 설정한
  값이 그대로인 항목만 복원한다.
- 기존 실행 중인 Claude Code 프로세스에는 설정이 적용되지 않으므로 연동 또는
  해제 뒤 재시작이 필요하다.

## 결과

### 장점

- Claude가 제공하는 요청 단위 토큰 수를 정확하게 집계한다.
- 여러 Claude Code 세션을 동일한 로컬 수집기로 통합한다.
- 사용자 콘텐츠와 계정 인증 정보가 RunDev 경계를 넘지 않는다.

### 단점

- RunDev가 실행 중이어야 새 이벤트를 받을 수 있다.
- 로컬 포트 충돌 시 수집이 중단된다.
- 사용자의 기존 OpenTelemetry 설정과 충돌할 수 있어 확인과 복원이 필요하다.

## 대안

- Claude 로그 파일 파싱: 내부 포맷 변경에 취약하고 정확한 토큰 정보가 보장되지 않는다.
- Anthropic 계정 API 조회: 로컬 Claude Code 세션과 안전하게 연결할 공개 계정 사용량
  API를 전제로 할 수 없다.
