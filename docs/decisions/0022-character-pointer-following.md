# 0022. 화면 캐릭터의 전역 포인터 따라다니기

- 상태: Accepted
- 날짜: 2026-08-07

## 맥락

화면 캐릭터의 우클릭 메뉴에서 사용자가 명시적으로 켜면 캐릭터가 다른 앱 위에서도
마우스 포인터를 따라다니는 기능을 제공한다. 이를 위해 앱 창 밖의 전역 포인터 좌표를
읽어야 하므로 ADR 0005의 최소 수집 원칙에 맞춰 사용 범위를 제한해야 한다.

## 결정

- 기능은 기본 비활성화하며 화면 캐릭터 우클릭 메뉴에서만 사용자가 켜고 끈다.
- 활성화된 동안에만 Rust가 OS의 현재 포인터 좌표를 읽어 캐릭터 창의 위치를 계산한다.
- 캐릭터는 포인터와 겹치지 않도록 포인터의 우하단에 간격을 두고 배치한다.
- 포인터 좌표, 이동 경로, 속도, 클릭 위치와 머문 위치는 SQLite, 로그, 진단 이벤트,
  React 이벤트에 기록하거나 전달하지 않는다.
- SQLite에는 `character.window.follow_pointer`의 활성 여부만 저장한다.
- 우클릭 메뉴가 열려 있는 동안에는 캐릭터 창 이동을 일시 중지한다.
- 기능을 끄면 마지막 캐릭터 창 위치에서 수동 드래그를 다시 허용한다.
- 따라다니는 캐릭터를 직접 클릭하기 어려우므로 트레이 아이콘 가운데 클릭으로 즉시
  숨길 수 있게 하며 기존 트레이 좌클릭 팝오버 동작은 유지한다.

## 결과

### 장점

- 입력 중인 캐릭터를 시선 가까이에 유지하면서 원본 포인터 경로를 보존하지 않는다.
- 포인터 접근과 창 이동을 Rust가 소유해 React 및 DB 경계를 유지한다.

### 단점

- 활성화 중 지속적인 OS 좌표 조회와 창 이동 비용이 발생한다.
- 플랫폼과 다중 모니터 배율에 따라 위치 표현 차이를 검증해야 한다.

## 대안

- React의 `mousemove` 사용: 캐릭터 창 안의 포인터만 관찰할 수 있어 제외했다.
- 포인터 이동 경로 저장: 기능에 필요하지 않고 개인정보 범위를 확대해 제외했다.
- 캐릭터를 포인터 바로 아래에 배치: 클릭 대상을 가릴 수 있어 우하단 간격을 선택했다.
