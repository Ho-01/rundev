# 0019. 서명된 로컬 XP 쿠폰

- 상태: Accepted
- 날짜: 2026-08-04

## 맥락

서버를 추가하지 않고 이벤트별 XP 배수와 적용 시간을 담은 쿠폰을 제공해야 한다.
앱에 비밀값을 포함한 쿠폰 방식은 실행 파일을 분석한 사용자가 쿠폰을 만들 수 있고,
XP 합계만 직접 수정하면 지급 근거를 추적할 수 없다.

## 결정

- 쿠폰은 `RDC1.<payload>.<signature>` 형식이며 Ed25519로 서명한다.
- payload에는 쿠폰 ID, 2배 또는 3배, 적용 시간(분), 등록 기한만 포함한다.
- 릴리스 빌드는 `RUNDEV_COUPON_PUBLIC_KEY` 공개키로 검증하고 비밀키는 저장소와 앱에
  포함하지 않는다.
- 사용 기록과 적용 구간은 `xp_coupon_redemptions`에 로컬 저장한다.
- 모든 기본 XP는 기존 `xp_events`에 기록하고 추가분은 `xp_boost_bonus` 이벤트로
  별도 기록한다.
- 이미 적용 또는 예약된 부스트가 있으면 새 쿠폰은 마지막 종료 시점부터 이어진다.
- 쿠폰 원문과 서명은 저장하지 않는다.

## 결과

### 장점

- 네트워크나 계정 없이도 쿠폰의 배수, 기간과 등록 기한을 위조 방지할 수 있다.
- 기본 지급과 부스트 보너스를 원장에서 독립적으로 감사할 수 있다.
- 비밀키 유출 없이 앱과 공개 저장소에 검증 기능을 배포할 수 있다.

### 단점

- DB 삭제나 다른 기기에서 같은 쿠폰을 사용하는 것은 서버 없이 차단할 수 없다.
- 시스템 시간 조작을 완전히 방지할 수 없다.
- 릴리스 전에 GitHub Actions 변수에 공개키를 설정해야 한다.

## 대안

- 서버 검증은 현재 제품 원칙과 운영 비용 때문에 제외했다.
- 앱에 쿠폰 목록이나 HMAC 비밀키를 포함하는 방식은 추출과 위조가 쉬워 제외했다.
