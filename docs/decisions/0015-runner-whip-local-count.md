# 0015. 개발자 캐릭터 채찍질 횟수의 로컬 집계

- 상태: Accepted
- 날짜: 2026-07-29

## 맥락

팝오버 헤더의 개발자 캐릭터를 클릭해 “채찍질”하는 가벼운 상호작용을 추가한다.
후속으로 AI 채팅 전달을 고려하지만, 1차는 피격 연출과 로컬 일별 횟수만 다룬다.
새로운 사용자 상호작용 집계이므로 ADR 0005 최소 수집 원칙에 맞춰 범위를
명시해야 한다.

## 결정

- 트리거는 팝오버 헤더 캐릭터 버튼 클릭만 허용한다. 트레이 좌클릭은 팝오버 토글만
  담당한다.
- SQLite `whip_daily_stats`에 로컬 날짜별 `whip_count`와 `updated_at`(UTC RFC3339)만
  저장한다.
- `local_date`는 Rust가 로컬 캘린더로 계산하며 React가 날짜를 넘기지 않는다.
- 증분은 단일 원자 UPSERT(`whip_count = whip_count + 1`)로 처리한다.
- XP/`xp_events`, 클릭 좌표, 연타 패턴, 메시지 본문, 시각 시퀀스는 저장하지 않는다.
- 데이터는 로컬에 무기한 보관하며, 향후 앱 데이터 초기화 기능이 삭제 대상에 포함한다.
- command payload와 count를 일반 로그·텔레메트리·crash report에 남기지 않는다.
- `record_whip`는 domain event, outbox, 채팅 callback을 발행하지 않는다.
- AI 채팅 전달은 별도 opt-in, 별도 ADR, 별도 command로만 추가한다. 이번 코드에
  채팅 hook이나 이벤트 버스를 미리 연결하지 않는다.

## 결과

### 장점

- 상호작용 피드백과 일별 집계를 개인정보 범위 안에서 제공한다.
- 키보드 일별 집계와 같은 패턴으로 도메인 경계가 명확하다.
- 후속 채팅 기능을 현재 스키마에 묶지 않아 수집 범위가 커지지 않는다.

### 단점

- 일별 합계만 있어 시간대별 패턴 분석은 할 수 없다.
- 클라이언트 쿨다운은 UX용이며, 정확성은 DB 원자성에 의존한다.

## 대안

- UI만 재생하고 저장하지 않음: 후속 기능과 일별 표시에 불리해 제외했다.
- `daily_activity_metrics` 재사용: 키보드 XP 경로와 의미가 섞여 전용 테이블을 선택했다.
- XP 연동: 1차 범위를 넘는 보상 설계가 필요해 제외했다.
