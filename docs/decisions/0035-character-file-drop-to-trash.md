# 0035. 플로팅 캐릭터 파일 드롭 휴지통 처리

- 상태: Accepted
- 날짜: 2026-08-10

## 맥락

플로팅 캐릭터가 모니터 자유 이동 중인지와 관계없이, 사용자가 파일 탐색기나 Finder의
파일을 캐릭터 위에 드롭하면 휴지통으로 보내고 먹는 연출을 제공한다. 파일의 원문이나
내용을 읽거나 저장하지 않으면서도 운영체제의 되돌릴 수 있는 휴지통 동작을 사용해야 한다.

## 결정

- Tauri의 캐릭터 webview 파일 드롭 이벤트를 사용한다. `enter`/`over`에서는 캐릭터 창의
  이동을 잠그고, 창을 48 logical px에서 88 logical px로 확대해 실제 드롭 영역도 함께
  확대한다. 확대와 축소는 창 중심을 유지한 채 여러 크기 프레임으로 보간한다.
- `leave`에서는 파일을 건드리지 않고 창 크기와 이동 잠금을 복구한다.
- `drop`에서 Rust command가 드롭된 regular file 경로를 검증한 뒤 Windows Shell의
  Recycle Bin 또는 macOS Foundation `NSFileManager`의 Trash로 이동한다.
- 휴지통 이동이 성공한 경우에만 React가 입 벌림 대기 이후 씹기·삼키기 연출을 실행한다.
  각 runner는 입 위치와 체형에 맞춘 `ready`/`bite`/`chew`/`swallow` 전용 PNG 프레임을
  사용하며, 운영체제 드래그 커서와 중복되는 파일 아이콘은 별도로 합성하지 않는다.
  애니메이션이 끝나면 창을 원래 크기로 복구하고, 자유 이동이 활성화되어 있었다면 Rust가
  이동을 재개한다.
- 경로는 드롭 처리 중에만 메모리에서 사용하며 SQLite, 로그, 이벤트 payload 외부에
  보존하지 않는다. 폴더 드롭은 초기 범위에서 거부한다.

## 결과

### 장점

- Windows와 macOS의 사용자 휴지통 동작을 사용하므로 실수한 파일을 복구할 수 있다.
- 이동 중단, 창 크기, 휴지통 처리와 같은 네이티브 동작은 Rust가 소유하고 React는
  시각 상태만 표시한다.
- 파일 내용, 파일명, 경로를 수집하거나 서버로 전송하지 않는다.

### 단점

- Windows와 macOS 휴지통 API를 각각 유지해야 한다.
- runner를 추가할 때는 캐릭터별 먹기 전용 PNG 네 프레임도 함께 제작해야 한다.

## 대안

- 파일을 직접 삭제하는 방식은 복구할 수 없어 채택하지 않는다.
- CSS로만 캐릭터를 확대하는 방식은 실제 OS 드롭 hitbox가 커지지 않아 채택하지 않는다.
