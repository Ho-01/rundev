# 0011. 활성 개발 앱과 입력 유휴 시간으로 집중시간 집계

- 상태: Accepted
- 날짜: 2026-07-28

## 맥락

대시보드의 `개발 도구 노려본 시간`은 사용자가 RunDev를 켜 둔 시간이나 키보드를 누른
시간 자체가 아니다. 실제 개발 도구를 사용하며 자리를 비우지 않은 시간만
일관되게 집계할 기준이 필요하다. 창 제목, 문서명, URL을 읽으면 분류 범위는
넓어지지만 개인정보 수집과 오분류 위험도 커진다.

## 결정

- Windows에서는 포그라운드 프로세스의 실행 파일명, macOS에서는 활성 앱의 bundle
  identifier를 내장 개발 앱 카탈로그와 정확히 비교한다.
- 앱 시작 시와 실행 중 1초 간격으로 활성 앱과 마지막 사용자 입력 이후 시간을
  확인한다.
- 카탈로그에 포함된 앱이 활성 상태이고 마지막 입력 후 5분 미만일 때만 집중시간을
  1초씩 누적한다.
- 비개발 앱 전환, 5분 idle 도달 또는 화면 잠금 시 현재 세션을 닫는다. 개발
  앱끼리 전환해도 앱별 추적을 위해 새 세션을 만든다.
- 절전 때문에 건너뛴 시간은 누적하지 않는다. 수집 루프가 실제로 실행한 tick만
  계산한다.
- UI에는 매초 메모리 합계를 이벤트로 전달하고 SQLite의 같은 세션 행은 10초
  단위와 세션 종료 시 갱신한다.
- 실행 파일명 또는 bundle identifier만 저장하며 창 제목, 파일 경로, URL, 키 입력
  내용은 읽거나 저장하지 않는다.
- 세션의 앱 식별자를 사람이 읽기 쉬운 앱 이름으로 변환해 마지막으로 본 개발 도구와
  오늘의 앱별 누적시간을 표시한다.
- 로컬 날짜별 누적 개발시간 30분마다 10 XP를 지급한다.
  `focus:{local_date}:{milestone}`을 `xp_events.source_event_id`로 사용해 같은
  마일스톤에는 한 번만 지급한다.
- 사용자 지정 앱 등록은 후속 기능으로 둔다. 기본 카탈로그 변경은 코드 리뷰와
  테스트를 거친다.

## 결과

### 장점

- 브라우저나 영상 앱을 켜 둔 시간을 개발 집중시간으로 계산하지 않는다.
- SQLite를 매초 쓰지 않으면서 화면에는 즉시 변화를 보여줄 수 있다.
- 30분 단위 XP가 원장에 남아 재시작이나 재집계에도 중복 지급되지 않는다.
- 절전·잠금·장시간 자리 비움이 집중시간을 부풀리지 않는다.
- 수집 정보가 앱 식별자로 제한되어 개인정보 노출 범위가 작다.

### 단점

- 새 IDE나 이름이 바뀐 앱은 카탈로그가 갱신되기 전까지 자동 인식하지 못한다.
- 범용 터미널은 개발 외 작업에도 사용될 수 있어 일부 과대 집계가 가능하다.
- 현재 OS 상태 확인 주기 때문에 중단 반영에 최대 약 1초가 걸릴 수 있다.
- 강제 종료 직전의 아직 저장하지 않은 집중시간은 최대 10초 유실될 수 있다. 다음
  시작 때 종료 시각이 비어 있는 세션은 마지막 저장 합계를 기준으로 정리한다.

## 대안

- 창 제목과 프로젝트 경로를 분석하는 방식은 정확도를 높일 수 있지만 개인정보
  원칙과 맞지 않아 선택하지 않았다.
- 키보드 입력이 발생한 순간만 더하는 방식은 읽고 생각하는 개발 시간을 놓쳐
  선택하지 않았다.
- 사용자가 모든 앱을 직접 등록하는 방식은 초기 설정 부담이 커 기본 카탈로그
  이후의 보완 기능으로 남겼다.
