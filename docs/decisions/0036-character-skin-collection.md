# 0036. 로컬 집중 마일스톤 기반 캐릭터 스킨 컬렉션

- 상태: Accepted
- 날짜: 2026-08-11

## 맥락

RunDev의 개발자 캐릭터는 트레이, 팝오버, 화면 위 플로팅 창에서 사용자의 동행자 역할을 한다.
기존에는 캐릭터 하나만 선택할 수 있어, 캐릭터별 외형을 추가하거나 잠금 보상을 제공할 수 있는
구조가 없었다. 스킨 보상은 제품 사용을 방해하거나 새로운 개인정보를 수집하지 않아야 한다.

## 결정

- 캐릭터 선택, 스킨 소유권, 캐릭터별 장착 상태를 분리한다. 기본 스킨은 항상 사용할 수 있고,
  잠금 스킨의 소유권은 SQLite `character_skin_ownership`에 저장한다. 캐릭터별 장착 스킨은
  `character_skin_loadout`에 저장한다.
- 첫 잠금 스킨인 `pool-party`는 핑크 버튜버 전용으로 제공한다. 기존에 로컬 집계하던
  `development` 활동 시간의 누적 5시간을 달성하면 자동 해금한다.
- 해금 조건 판정과 소유권 기록은 Rust가 담당한다. React는 Tauri command로 컬렉션 상태를
  읽고 장착 요청만 보낸다.
- 해금에 새 데이터 수집, 서버 동기화, 로그인, 결제, 출석, 확률형 보상을 추가하지 않는다.
- 스킨은 트레이, 팝오버, 플로팅 캐릭터에 같은 외형으로 표시한다. 플로팅 캐릭터의 기본,
  파일 먹기, 잡힘, 자유 이동 상태는 스킨별 프레임 묶음으로 관리한다. 수영장 파티 스킨의
  자유 이동은 걷기 대신 서핑보드 모션을 사용한다.

## 결과

### 장점

- 이미 최소 수집 범위에 포함된 집계 시간만 이용하므로 개인정보 원칙을 유지한다.
- 사용자가 앱을 실제로 활용한 결과로 외형을 얻되, 일일 접속이나 결제를 강요하지 않는다.
- 캐릭터와 스킨을 독립적으로 확장할 수 있고, 새 스킨을 추가해도 기존 장착값이 충돌하지 않는다.
- 스킨별 상태 프레임을 강제해 입 위치·캐릭터 크기·이동 모션의 불일치를 예방한다.

### 단점

- 스킨 하나마다 여러 상태의 PNG 프레임과 트레이 아이콘을 함께 제작해야 한다.
- 누적 활동 시간은 사용자의 장기 사용 이력에 따라 즉시 해금될 수 있으므로, 출시 후 조건의
  난이도는 조정이 필요할 수 있다.

## 대안

- XP 소비: 성장과 외형 수집을 경쟁시키므로 제외한다.
- 집중 칩 구매: 작업실 보상 체계와 결합해 첫 캐릭터 스킨의 이해 비용을 높이므로 제외한다.
- 출석·연속 접속: 사용자를 앱에 묶는 방향이라 제외한다.
- 서버 계정 기반 업적: 로컬 우선 원칙과 MVP 범위를 벗어나므로 제외한다.
