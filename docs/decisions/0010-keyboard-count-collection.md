# 0010. 키 입력 횟수의 로컬 집계

- 상태: Accepted
- 날짜: 2026-07-28

## 맥락

RunDev는 개발 활동에 즉각적인 피드백을 주기 위해 하루 동안 사용자가 키보드를
두드린 횟수를 보여주고, 2,000회마다 10 XP를 지급하려 한다. 전역 키 입력 감지는
입력 내용까지 관찰할 수 있는 민감한 OS 기능이므로 수집 범위와 저장 방식을
명시적으로 제한해야 한다.

## 결정

- 앱 실행 시 키보드 집계를 자동으로 시작한다.
- 키 코드, 문자, 입력 순서, 입력 대상 앱은 저장하거나 로그로 남기지 않는다.
- 네이티브 수집기는 키 코드를 자동 반복과 보조키 판정에만 순간적으로 사용하고
  즉시 버린다. 키 코드는 command, DB, 파일, 로그로 전달하지 않는다.
- Shift, Control, Alt, Command, Caps Lock 같은 단독 보조키는 집계하지 않는다.
- 개별 키 이벤트는 DB에 저장하지 않고 `keyboard_daily_stats`에 로컬 날짜별
  누적 횟수만 저장한다.
- 2,000회 단위마다 `keyboard:{local_date}:{milestone}`을
  `xp_events.source_event_id`로 사용하여 10 XP를 한 번만 지급한다.
- macOS에서는 Input Monitoring 권한을 확인하고 최초 미허용 시 시스템 요청과
  설정 화면을 제공한다. 권한 허용 전에는 집계하지 않는다.
- Windows에서는 숨겨진 메시지 전용 창에 Raw Input 키보드를 등록하며, 일반 사용자
  세션에서 별도 관리자 권한 없이 수집기를 시작한다.
- 입력은 메모리에서 누적하고 250ms 단위 Rust 이벤트로 화면의 키 입력 수치만 갱신한다.
- SQLite에는 5초마다 누적 합계를 한 번 저장하고 날짜 변경과 수집 채널 종료 시 남은
  값을 저장한다.
- 로그인 화면, UAC 보안 화면 및 OS가 전달하지 않는 입력은 집계 대상이 아니다.

## 결과

### 장점

- 입력 내용이 저장되지 않아 개인정보 노출 범위를 최소화한다.
- XP 지급이 원장과 고유 source ID로 중복 방지된다.
- 날짜별 집계가 향후 활동 잔디 화면의 입력 데이터로 사용될 수 있다.

### 단점

- macOS 사용자는 입력 모니터링 권한을 직접 허용해야 한다.
- OS나 키보드 드라이버에 따라 실제 물리 입력과 집계 횟수가 조금 다를 수 있다.
- 개별 이벤트를 저장하지 않으므로 과거 입력 패턴을 재분석할 수 없다.

## 대안

- 입력한 키 코드 또는 문자열 저장
- RunDev 창이 활성화된 동안만 집계
- 개발 활동 시간을 키 입력 횟수의 대용 지표로 사용
