# ADR 0018: 제한된 로컬 진단 로그

## 상태

Accepted

## 배경

RunDev는 사용자 장비에서만 발생하는 운영체제 권한, event tap, 로컬 DB 저장
문제를 원격에서 재현하기 어렵다. 현재 tracing 출력은 콘솔에만 기록되어 배포된
트레이 앱에서는 사용자가 진단 자료를 제공할 수 없다.

키 입력 감지 문제를 진단하려면 권한 판정, 감지기 시작, 첫 집계 신호, 첫 저장
단계 중 어디에서 멈췄는지 확인할 수 있어야 한다. 그러나 일반 애플리케이션 로그는
파일 경로, 계정 정보, 입력 값 같은 민감정보가 우발적으로 섞일 위험이 있다.

## 결정

- 앱 데이터 디렉터리의 `diagnostics/`에 전용 JSON Lines 로그를 기록한다.
- 일반 tracing 출력을 그대로 저장하지 않고, 코드에서 명시한 진단 이벤트와
  제한된 필드만 기록한다.
- 로그에는 앱 버전, OS/CPU 대상, 프로세스 ID, 키보드 감지 상태 전이,
  Input Monitoring 권한 여부, event tap 생성 결과, 첫 집계 신호와 첫 DB 저장
  여부만 포함한다.
- 키 값, 키 입력 순서, 창 제목, 파일 경로, 프롬프트, 응답, 소스 코드, 계정 식별자,
  인증정보는 기록하지 않는다.
- 현재 파일은 1 MiB에서 회전하고 최근 파일 3개만 유지한다.
- 사용자가 직접 진단 폴더를 열어 파일을 확인하고 공유할 수 있게 한다. 자동 업로드
  또는 서버 전송은 추가하지 않는다.

## 결과

- 사용자 장비에서 입력 감지 파이프라인의 실패 단계를 구분할 수 있다.
- 로그 공유는 사용자의 명시적 행동으로만 발생한다.
- 일반 tracing 오류 전체를 파일에 남기지 않으므로 진단 범위는 의도적으로
  제한된다. 새로운 이벤트나 필드를 추가할 때 개인정보 경계를 다시 검토해야 한다.
