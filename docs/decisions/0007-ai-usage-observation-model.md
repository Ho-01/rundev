# 0007. AI 사용량의 이벤트와 스냅샷 분리

- 상태: Accepted
- 날짜: 2026-07-28

## 맥락

AI 도구는 사용량을 서로 다른 형태로 제공한다. OpenTelemetry는 개별 요청의
증분 토큰을 제공하지만 Codex 계정 사용량 API는 날짜별 누적 합계를 제공한다.
두 값을 같은 이벤트로 저장하고 합산하면 동기화할 때마다 토큰이 중복 집계된다.

로컬 대화 기록에는 프롬프트와 도구 출력이 포함될 수 있으므로 사용량 수집을
위해 이를 파싱하는 것은 개인정보 최소 수집 원칙과 맞지 않는다.

## 결정

- 요청별 증분은 `ai_usage_events`에 저장한다.
- 계정·날짜별 누적값은 `ai_usage_snapshots`에 저장한다.
- 일별 총량은 최신 공식 스냅샷을 우선하고, 스냅샷이 없을 때만 이벤트 합계를 사용한다.
- 스냅샷과 이벤트를 더하지 않는다.
- 첫 번째 어댑터는 Codex App Server의 `account/usage/read`를 사용한다.
- 어댑터는 기본적으로 비활성화하며 사용자가 UI에서 명시적으로 연동한 뒤에만
  Codex CLI의 기존 로그인 세션을 사용한다.
- 연동 전 `account/read`로 계정 식별 정보와 인증 환경을 표시하고 사용자의
  확인을 한 번 더 받은 뒤 사용량 수집을 활성화한다.
- RunDev는 Codex 인증정보와 원본 JSON 응답을 저장하지 않는다.
- 프롬프트, 응답, 소스 코드, 대화 transcript를 수집하지 않는다.
- 1차 구현에서는 토큰을 XP로 변환하지 않는다.
- 계정 일별 버킷은 실시간 데이터로 간주하지 않는다. 오늘 버킷이 아직 없고
  이전 날짜 버킷이 존재하면 `0`이 아니라 집계 지연과 최신 제공 날짜를 표시한다.

## 결과

### 장점

- 주기적 동기화가 중복 집계를 만들지 않는다.
- 향후 Codex와 Claude OpenTelemetry 이벤트를 동일한 모델로 확장할 수 있다.
- 사용량 수집 과정에서 대화 내용을 읽지 않는다.

### 단점

- 계정 스냅샷만 존재할 때는 입력·출력·모델별 분석을 제공할 수 없다.
- 계정 사용량에는 다른 장치에서 발생한 사용량도 포함될 수 있다.

## 대안

- 로컬 transcript 파싱: 비공개 형식에 의존하고 민감한 원문에 접근하므로 제외한다.
- 모든 측정값을 단일 테이블에 저장: 집계 오류 가능성이 높아 제외한다.
