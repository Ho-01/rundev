# 0038. 세로형 적응식 트레이 팝오버 크기

- 상태: Accepted
- 날짜: 2026-08-14

## 맥락

기본 340×480 크기는 오른쪽 52px 장치 요약 레일을 포함하던 시점에 정했다. 장치와
통계 진입점을 헤더와 좌우 확장 패널로 옮긴 뒤 외부 창 크기는 같지만 실제 본문 폭은
약 286px에서 318px 이상으로 넓어졌다. 반면 성장, 활동, AI 사용량이 세로로 이어져
본문의 작은 보조 글자와 스크롤 밀도는 높아졌다.

트레이 팝오버의 가로 점유를 줄이면서 핵심 숫자와 설명의 가독성을 높이고, 작은 작업
영역에서도 화면 밖으로 벗어나지 않는 크기 정책이 필요하다.

## 결정

- 선호 기본 크기는 320×520 logical pixel이다.
- 좌우 상세 패널 172px을 열면 492×520으로 확장한다.
- 현재 모니터의 작업 영역에 상하 8px 여백을 포함해 520px이 들어가지 않으면 높이를
  480px로 낮춘다. 480px도 들어가지 않으면 작업 영역 안에서 최소 400px까지 줄인다.
- 프론트엔드는 고정 높이 대신 실제 WebView viewport 높이를 사용한다.
- 핵심 상태와 성장 카드의 보조 글자를 키우고, 세부 정보는 스크롤과 확장 패널에 둔다.
- 좌우 패널을 열고 닫을 때 본문 폭 320px은 유지한다.

## 결과

### 장점

- 이전보다 가로로 퍼져 보이는 인상을 줄이면서 전체 화면 면적은 거의 유지한다.
- 선호 높이에서는 핵심 정보 사이의 세로 여백과 텍스트 가독성을 높일 수 있다.
- Windows 디스플레이 배율과 macOS의 작은 작업 영역에서도 팝오버가 잘리지 않는다.
- 기본 폭과 확장 패널 폭의 합이 명확해 패널 전환 중 본문 흔들림을 막기 쉽다.

### 단점

- 작업 영역에 따라 같은 앱 버전의 팝오버 높이가 달라질 수 있다.
- 480px 이하 환경에서는 일부 내용을 보기 위한 세로 스크롤이 더 필요하다.
- 기존 340px 폭을 전제로 만든 문구와 모달을 다시 검수해야 한다.

## 대안

- 기존 340×480 고정 크기 유지
- 360px 이상으로 넓혀 모든 정보를 한 화면에 표시
- 사용자가 팝오버 자체를 자유롭게 리사이즈
