# 0009. AI 세션 활동은 익명 키와 최근 이벤트로 집계

- 상태: Accepted
- 날짜: 2026-07-28

## 맥락

대시보드에서 AI 공급자별 실제 사용 세션 수와 최근 활동 여부를 보여주려 한다.
Claude Code OpenTelemetry 이벤트는 `session.id`를 제공하지만 원본 세션 식별자를
장기 저장할 필요는 없다. Codex 계정 사용량은 일간 합계이며 세션 식별자를 제공하지
않는다.

## 결정

- Claude Code의 `session.id`는 수집 즉시 SHA-256으로 해시한다.
- 원본 `session.id`는 DB와 로그에 저장하지 않는다.
- 해시한 `session_key`를 요청 이벤트에 기록해 오늘의 고유 세션 수를 계산한다.
- Claude의 최근 활성 여부는 최근 15분 이내 세션 이벤트로 판정한다.
- Codex의 최근 활성 여부는 일간 계정 토큰 스냅샷이 직전 값보다 증가하고 그 관측이
  최근 15분 이내일 때만 추론한다.
- Codex에는 정확한 세션 수를 표시하지 않는다.
- 상단 합계는 세션 수가 아니라 최근 활성 상태인 AI 공급자 수다.

## 결과

### 장점

- Claude의 여러 터미널과 IDE 세션을 원문 없이 구분할 수 있다.
- Codex의 계정 합계를 세션 수로 잘못 표현하지 않는다.
- 이벤트 원장에서 기간별 고유 세션 수를 다시 계산할 수 있다.

### 단점

- Claude 연동 이전 이벤트에는 `session_key`가 없어 세션 수에 포함되지 않는다.
- 동일 Claude 세션이 여러 날짜에 걸치면 각 날짜의 사용 세션으로 집계된다.
- Codex 활성 여부는 계정 스냅샷 기반 추론이며 최대 폴링 주기만큼 늦을 수 있다.

## 대안

- 원본 세션 ID 저장: 집계에 불필요한 외부 식별자를 보관하므로 제외했다.
- CLI 프로세스 개수 집계: IDE와 설치 방식에 따라 프로세스와 세션이 일치하지 않아
  제외했다.
- Codex 저장 대화 목록 사용: 프롬프트 preview를 읽을 위험이 있고 다른 프로세스의
  런타임 상태를 정확히 보장하지 않아 제외했다.
