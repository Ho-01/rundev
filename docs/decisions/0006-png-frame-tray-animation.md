# 0006. PNG 프레임 트레이 애니메이션

- 상태: Accepted
- 날짜: 2026-07-28

## 맥락

Windows와 macOS 트레이는 GIF 애니메이션을 일관되게 재생하지 않는다. RunDev는
상태와 개발 활동에 따라 개발자 캐릭터 동작과 속도를 바꿔야 한다.

## 결정

- 제작 기준은 투명한 256×256 마스터 프레임으로 저장한다.
- React 화면은 마스터에서 생성한 128×128 UI 프레임을 사용한다.
- 네이티브 트레이는 작은 OS 표시 영역에 맞춘 별도의 32×32 프레임을 사용한다.
- Rust 타이머가 현재 상태에 맞춰 `TrayIcon::set_icon`을 호출한다.
- 기본 coding 애니메이션은 4프레임을 170ms 간격으로 반복한다.
- 지원 개발자 캐릭터는 동일한 4프레임 계약을 지키며, 선택값은
  `app_settings.runner.selected`에 저장한다.
- 트레이 프레임은 기본 검은 고양이의 28×22 피사체 안전 영역을 기준으로
  정규화한다. 마스터와 UI 프레임은 이 비율을 각각 8배와 4배로 유지한다.
- Rust 트레이와 React 헤더는 같은 개발자 캐릭터 ID와 프레임 디렉터리를 사용한다.
- 특정 좌측 영역을 첫 프레임 픽셀로 덮어쓰지 않는다. 이 방식은 캐릭터 몸체까지
  고정하거나 얼굴을 손상할 수 있으므로, 소품의 안정성과 캐릭터 움직임은 원본
  스프라이트 단계에서 함께 설계한다.
- 고양이와 노트북의 명암 구분을 유지하기 위해 macOS에서도 컬러 PNG를 그대로
  사용하며 template icon으로 강제 변환하지 않는다.
- Windows와 macOS 표현이 달라지면 플랫폼별 애셋 디렉터리를 추가한다.
- 원본 스프라이트 변환은 `scripts/build-tray-animation.mjs`로 재현한다.

## 결과

### 장점

- 프레임 속도를 활동량에 따라 동적으로 바꿀 수 있다.
- OS별 아이콘 처리 차이를 제어할 수 있다.
- idle, coding, sleeping, level-up 상태로 확장하기 쉽다.
- 프레임 디렉터리로 개발자 캐릭터를 추가할 수 있고 README용 GIF도 같은 원본에서 생성한다.
- 현재 패키지에는 기본·주황 고양이, 주황 새우, 노란 물고기, 핑크 버튜버가 포함된다.

### 단점

- 너무 빠른 아이콘 교체는 CPU 사용량을 높일 수 있다.
- 32px에서 읽히도록 애셋을 별도로 최적화해야 한다.
- 프레임 수가 늘면 바이너리 크기와 메모리 사용량이 증가한다.

## 대안

- GIF를 트레이 아이콘으로 설정
- 정적 아이콘 하나만 사용
- 플랫폼별 네이티브 애니메이션 구현
