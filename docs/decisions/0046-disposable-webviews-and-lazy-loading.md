# ADR 0046: 화면 수명 관리와 기능별 지연 로딩

- 상태: 채택
- 날짜: 2026-11-17

## 배경

v0.7.0은 숨긴 메인·캐릭터·급여 창을 모두 시작할 때 생성했다. 세 창이 같은
진입점에서 모든 화면 코드와 물리 엔진을 불러왔고 숨긴 메인 창에서도 일부 조회
타이머가 유지됐다. 쓰지 않는 화면의 실행 환경과 중복 조회를 줄여야 한다.

## 결정

- 세 창 모두 `create: false`로 선언하고 Rust `window_lifecycle`이 필요할 때 생성한다.
- Windows WebView2의 동기 이벤트 핸들러 생성 교착을 피하도록 트레이 열기는 별도
  스레드에서 만들고 시작 시 캐릭터 복원도 비동기 작업에서 실행한다.
- 메인 팝오버는 숨김 즉시 화면 조회를 중단하고 30초 뒤 파괴한다. 30초 안에 다시
  열면 재사용한다. 세대 번호와 메인 스레드의 최종 가시성 확인으로 재열기와
  파괴 예약 사이의 경쟁을 방지한다.
- 플로팅을 끄면 위치를 저장한 뒤 캐릭터·급여 창을 파괴한다. 다시 켜면
  위치·크기·따라가기·배회 설정을 SQLite에서 복원한다.
- 급여 창은 플로팅이 보이고 급여 설정이 있을 때만 만든다. 클릭 통과 창은
  캐릭터의 드래그·크기 조절 영역과 겹침 순서를 보존하기 위해 유지한다. 상주하지
  않으며 대시보드·물리 엔진·캐릭터 이미지 카탈로그를 로딩하지 않는다.
- `main.tsx`에서 현재 창에 해당하는 React 트리만 동적 import한다. 도감·통계·특성
  화면과 채찍 물리 엔진도 첫 사용 시 로딩한다. 도감 이미지는 lazy/async로 표시한다.
- 급여 카드와 캐릭터 표시가 메인 창에서 하나의 급여 스냅샷을 공유한다.
- 숨긴 메인 창의 AI 캐시·급여·부스트·업데이트 화면 타이머를 정지한다. 계정 한도
  주기 조회도 메인 창이 보일 때만 하며 다시 열 때 즉시 갱신한다.
- 개발 시간·키 횟수·XP·DB·트레이는 웹뷰와 독립적으로 유지한다. 마지막 창을
  파괴해도 앱이 종료되지 않으며 명시적인 종료 명령은 그대로 처리한다.

## 결과와 제약

유휴 상태에서 웹뷰가 없어도 수집과 트레이는 동작한다. 오래 숨겼다가 다시 열면
최초 로딩 시간이 들고 일시적인 폼·열린 모달 상태는 초기화된다. 저장한 설정은
보존된다. JS 모듈 캐시는 모달을 닫는 즉시 해제되지 않고 웹뷰 파괴 때 해제된다.

메모리는 같은 개발 모드·동일한 플로팅 상태에서 프로세스 트리로 비교한다. Vite와
Cargo는 별도이며 Working Set 합계는 공유 페이지를 중복 포함할 수 있다. 기능별
독점 메모리나 출시 빌드 수치로 해석하지 않는다.
