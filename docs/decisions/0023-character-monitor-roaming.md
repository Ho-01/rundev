# 0023. 플로팅 캐릭터의 모니터 자유 이동

- 상태: Accepted
- 일자: 2026-08-07

## 배경

플로팅 캐릭터를 꺼내 둔 동안 사용자의 화면에 생동감을 더하면서도, 포인터 따라다니기와 수동 드래그를 방해하지 않는 선택적 동작이 필요하다. 이동 중 노트북 모니터가 함께 보이면 캐릭터가 화면을 들고 미끄러지는 것처럼 보이므로 이동 전용 스프라이트가 필요하다.

## 결정

- 자유 이동은 플로팅 캐릭터의 우클릭 메뉴와 트레이 메뉴에서 토글한다. 기본값은 꺼짐이다.
- 포인터 따라다니기와 자유 이동은 동시에 켤 수 없다. 포인터 따라다니기를 켜면 자유 이동을 끈다.
- Rust가 현재 모니터의 작업 영역, 창 크기, 목적지 선택, 속도·호(arc) 보간, 메뉴가 열린 동안의 일시 정지를 소유한다.
- Rust는 이동 시작·종료 시 `character-window-motion-changed` 이벤트만 전달한다. React는 이벤트에 따라 러너별 4프레임 이동 전용 스프라이트 시퀀스와 방향·CSS 애니메이션을 표시한다.
- 이동 스프라이트에는 노트북 모니터를 포함하지 않는다. 이동 프레임은 기존 데스크톱 애니메이션과 같은 4프레임 주기로 약 170ms마다 교체하며, 이동이 끝나면 기존 데스크톱 스프라이트로 돌아간다.
- 설정은 `app_settings`의 `character.window.roaming`에 저장한다. 이동 경로 좌표는 저장하거나 네트워크로 전송하지 않는다.
- 목적지는 현재 모니터 작업 영역 안쪽의 제한 구역으로 제한하고, 이동 루프는 이동 중 약 33ms, 대기 중 약 120~250ms 주기로 실행한다. 이동 사이 대기 시간은 약 1.2~7.8초, 이동 속도는 약 140~360px/s 범위에서 매번 독립적으로 무작위 선택한다. 로밍 중 수동 드래그가 시작되면 이동을 일시 정지하고, 드래그가 끝난 뒤 다시 대기 후 재개한다.

## 대안

- 마우스 이동 이벤트마다 캐릭터를 갱신하는 방식은 포인터 따라다니기와 경쟁하고 불필요한 OS 창 이동을 늘리므로 채택하지 않는다.
- React 타이머로 좌표를 계산하는 방식은 창 위치·모니터 경계의 소유권을 흐리므로 채택하지 않는다.
- 이동 경로를 DB에 기록하는 방식은 복원 가치가 없고 개인정보·저장량을 늘리므로 채택하지 않는다.

## 결과

자유 이동은 기본 동작을 바꾸지 않는 opt-in 기능으로 제공된다. 이동 중에는 가벼운 이벤트와 이미지 교체만 수행하므로 기존 활동 수집이나 주 화면 렌더링과 분리된다.
